# 变更记录 2026-10-06

## 2026-10-06 11:39:28 批次1：编辑器模块修复

依据 `docs/CODE-REVIEW-FINAL-20261006.md` 落地，本批仅改 `src/src/app/note/[id].tsx` 一个文件。

1. **修复长便签无法滚动（回归修复，高优先级）**
   - 成因：上一提交 c61f6e2 把裸 `TextInput` 改为 `ScrollView(flexGrow:1)` + `Pressable(minHeight:'100%')` + `TextInput(flex:1, scrollEnabled={false})`。ScrollView 的 content 高度被固定为视口高度、没有可滚动溢出，而 TextInput 自身滚动又被禁用，长文本被裁剪且无法滚动。
   - 修法：阅读态与编辑态拆分——阅读态用 `ScrollView` + `Text`（随内容撑开，天然可滚动），编辑态以 `TextInput` 自身为滚动主体（恢复默认 `scrollEnabled`）。
   - 附带效果：`editable` + `pointerEvents` 双重开关随 `isEditing` 分支一并消除；编辑态不再支持「拖拽收起键盘」（改由完成按钮/返回键收起）。
   - 已知代价：从阅读态进入编辑态时输入框滚动位置回到顶部。
   - 样式：`scrollContent`/`editorPressable` → `readContent`/`readPressable`；`editor` 保持 `flex:1 + minHeight:200`。

2. **空便签返回判定去掉渲染闭包依赖（中）**
   - `handleBack` 原先用渲染闭包里的 `note.content` 与 `draft` 双条件判定，闭包可能读到过期值。
   - 改为 `flush()` 之后从 `notesStore.getState().notes` 取该 id 的最新行，`content === ''` 即 purge。语义随之变为「返回时已落库内容为空即丢弃」。

3. **移除语义无效的「放弃更改」菜单项（中）**
   - 500ms 防抖早已把内容落库，该操作既不回滚也不清除，属误导性 UI；返回键本就是「保存并退出」。菜单现只保留「归档便签」。
