## 2026-10-06 11:46:45 批次3：同步刷新收口与「导入进入同步流」

依据报告 5.2 / 5.5 + §2-1，改动 `sync/syncRunner.ts`、`app/_layout.tsx`、`app/index.tsx`、`app/settings/index.tsx`、`app/settings/sync.tsx`、`stores/notesStore.ts`。

1. **新增 `setAfterSync` 收口回调（高）**
   - `syncRunner` 增加 `setAfterSync(fn)` 并导出，与 `setSyncStateListener` 同一注入模式（避免循环导入）。
   - 调用点放在 `runAfterSyncHook` 的 **finally** 中，即成功与失败两条路径都执行：上行失败前引擎可能已经应用了部分下行，只有刷新后这些数据才会出现在界面上。仅「未启用/配置不完整而什么都没跑」时不执行。
   - 回调内部 try/catch，收口失败不会污染本轮同步结果（已加单测覆盖）。
   - `_layout.tsx` 在模块作用域注册 `setAfterSync(() => notesStore.getState().refreshAsync())`。
   - 相对报告的改进：报告只要求「成功分支调用」，实际按成功/失败双路径收口更贴合引擎「先下行后上行、上行失败即抛」的行为。

2. **下拉刷新改为两段式（高）**
   - 原实现 `Promise.race([runNow, 1200ms])` 后固定刷新，慢网下过早收起、且刷新依赖调用方手动执行。
   - 改为：先启动本轮 → `await refreshAsync()` 立即呈现本地数据（毫秒级）→ 再以 15 秒上限等本轮结束；该上限**只决定转圈何时收起、不中断同步**，同步完成后的刷新由收口保证。
   - 相对报告的改进：报告主张「直接去掉 1200ms 上限」，那会让慢网下转圈绑在整轮同步上（后端单请求超时 10s、下载并发 6，一轮可达数十秒）；两段式兼顾即时反馈与有界转圈。

3. **移除散落的刷新调用**
   - `_layout.tsx` 前台轮次的 `.finally(refreshAsync)`、`settings/sync.tsx` 两处 `runNow()` 后的 `refreshAsync()` 均由收口替代（前者删除，后者删除并移除不再使用的 `notesStore` 导入）。
   - `settings/sync.tsx` 的失败提示文案补上「配置不完整」（`runNow` 提前返回的真实原因之一）。

4. **导入进入同步流（高，报告 §2-1 两轮历史报告均遗漏）**
   - 新增 `notesStore.importAppliedAsync()`：先 `refreshAsync()` 让导入结果立刻出现在列表（调用方 await），再后台触发一轮 `performSyncRound('import')`（失败只记日志，不影响导入结果）。
   - `settings/index.tsx` 的 `onImport` 在 `imported > 0` 时调用它。此前导入只落 SQLite，既不刷新 store 也不触发同步，导入的数据要等到某条便签下次被编辑才可能碰巧上行。

## 2026-10-06 11:43:18 批次2：同步并发互斥与状态机

依据报告 3.6(修正后) / 5.8 / 5.9 落地，改动 `sync/syncRunner.ts`、`stores/syncStore.ts`、`components/SyncDot.tsx`、`app/index.tsx`。

1. **单飞从实例级提升到模块级（并发轮次改为合并，而不是丢弃）**
   - 成因：`engine.ts` 的 `running` 是实例字段，而 `syncRunner` 每轮 `new SyncEngine()`，注释所称的「单飞信号量」实际失效。
   - 修法：`syncRunner` 增加模块级 `inFlight` Promise。并发调用**返回同一个 Promise**并入正在跑的那一轮，而不是各自起一轮全量对账；一轮 `.finally` 后释放。
   - 相对报告的改进：报告建议「丢弃本轮」，但那样 `runNow`/下拉刷新拿不到结果；合并既省流量又能让调用方拿到真实 summary。
   - 注：`engine.runAsync` 的实例级守卫保留不动（`syncEngine.test.ts` 直接依赖该语义）。

2. **`syncStore` 状态机：`inFlight` 由事件统一驱动 + 终态回落 idle**
   - 新增 `inFlight` 字段与 `markStarted`/`markFinished`，由 syncRunner 新增的 `start`/`end` 事件驱动，**与触发入口无关**——防抖/前台/后台轮次现在也会正确点亮指示点，「立即同步」的守卫也因此不再被防抖轮次绕过。
   - `status` 的终态（success/error）在 8 秒后定时回落 `idle`（`lastError` 保留供诊断）。
   - `SyncDot` 转圈改由 `inFlight` 驱动；`app/index.tsx` 传入该字段。
   - 顺带删除 write-only 字段 `syncStore.lastSummary`（无消费者，报告 3.2）。

3. **修复「同步状态永久卡在 syncing」**
   - 成因：`runNow` 先置 `status='syncing'` 再调 `performSyncRound`；后者在「已启用但配置不完整」时（`backendFactory` 返回 null）**提前 return 且不发任何事件**，状态再也不会复位，且 `status==='syncing'` 守卫会让后续所有手动同步被拒。
   - 修法：`runNow` 改为先判 `inFlight` 再置状态，并在 finally 中兜底把残留的 `syncing` 复位为 `idle`；`inFlight` 一律交给事件维护（避免把「本轮刚结束后启动的下一轮」误清零）。

### 新增单测

- `__tests__/syncRunner.test.ts`：并发两轮合并为同一 Promise / 单飞释放后可再跑 / 未启用与配置不完整两条提前返回路径不广播任何事件。
- `__tests__/syncStore.test.ts`：inFlight 生命周期、终态 8 秒回落 idle、错误态保留 lastError、`runNow` 并发拒绝、提前返回不卡 syncing。

## 2026-10-06 11:39:28 批次1：编辑器模块修复

依据 `docs/CODE-REVIEW-FINAL-20261006.md` 落地，本批仅改 `src/src/app/note/[id].tsx` 一个文件。

1. **修复长便签无法滚动（回归修复，高优先级）**
   - 成因：上一提交 c61f6e2 把裸 `TextInput` 改为 `ScrollView(flexGrow:1)` + `Pressable(minHeight:'100%')` + `TextInput(flex:1, scrollEnabled={false})`。ScrollView 的 content 高度被固定为视口高度、没有可滚动溢出，而 TextInput 自身滚动又被禁用，长文本被裁剪且无法滚动。
   - 修法：阅读态与编辑态拆分——阅读态用 `ScrollView` + `Text`（随内容撑开，天然可滚动），编辑态以 `TextInput` 自身为滚动主体（恢复默认 `scrollEnabled`）。
   - 附带效果：`editable` + `pointerEvents` 双重开关随 `isEditing` 分支一并消除；编辑态不再支持「拖拽收起键盘」（改由完成按钮/返回键收起）。
   - 已知代价：从阅读态进入编辑态时输入框滚动位置回到顶部。
   - 样式：`scrollContent`/`editorPressable` → `readContent`/`readPressable`；`editor` 保持 `flex:1 + minHeight:200`。

2. **空便签返回判定去掉渲染闭包依赖（中）**
   - `handleBack` 原先用渲染闭包里的 `note.content` 与 `draft` 双条件判定，闭包可能读到过期值。
   - 改为 `flush()` 之后从 `notesStore.getState().notes` 取该 id 的最新行，`content === ''` 即 purge。语义随之变为「返回时已落库内容为空即丢弃」。

3. **移除语义无效的「放弃更改」菜单项（中）**
   - 500ms 防抖早已把内容落库，该操作既不回滚也不清除，属误导性 UI；返回键本就是「保存并退出」。菜单现只保留「归档便签」。
