## 2026-10-06 12:57:38 批次9：修复编辑态上下滑动误触选词弹窗

用户反馈：进入便签编辑模式、键盘弹出后，手指上下滑动滚动不顺畅，且经常误触发 TextInput 的"选择/全选"内置弹窗（ActionMode），弹窗一出后续滑动无法滚动。

1. **根因**：编辑态此前是裸 `TextInput` 作为滚动主体。Android 端 `ReactEditText` 强制 `setTextIsSelectable(true)`，且在 `ACTION_DOWN` 里禁止父容器拦截触摸；其内"竖向滚动"与"长按选词"共用同一套 touch 流程，稍慢一点的滑动很容易被系统判成长按选词，弹出 ActionMode（复制/全选等），弹窗抢走 touch 导致后续无法滚动。`scrollEnabled` 在 RN 0.86 Android 中无实现，`contextMenuHidden` 只是不绘制菜单，均不能根治手势竞争。
2. **修法**：`[id].tsx` 编辑态改为外层 `ScrollView` 承担垂直滚动，`TextInput` 自身 `scrollEnabled={false}` 且不再限高。新增 `editorHeight`/`editViewport` 两个 state：`ScrollView.onLayout` 记录视口高度，`TextInput.onContentSizeChange` 记录文本高度（+上下 padding），`height: Math.max(editorHeight, editViewport)` 使输入框恒等于文本高度、内部无溢出。这样 EditText 永不自身滚动，`ACTION_MOVE` 会还给父容器 `ScrollView`，滑动只被 ScrollView 消费，不再触发选词弹窗；真正的长按仍可唤起复制/全选菜单。样式 `editor` 移除 `flex:1/minHeight:200`，新增 `editContent` 容器样式。
3. **验证**：`tsc --noEmit` 通过、`expo lint` 无问题、Jest 109 passed / 7 skipped。

## 2026-10-06 11:39:28 批次1：编辑器模块修复

依据 `docs/CODE-REVIEW-FINAL-20261006.md` 落地，本批仅改 `src/src/app/note/[id].tsx` 一个文件。

1. **修复长便签无法滚动（回归修复，高优先级）**
   - 成因：上一提交 c61f6e2 把裸 `TextInput` 改为 `ScrollView(flexGrow:1)` + `Pressable(minHeight:'100%')` + `TextInput(flex:1, scrollEnabled={false})`。ScrollView 的 content 高度被固定为视口高度、没有可滚动溢出，而 TextInput 自身滚动又被禁用，长文本被裁剪且无法滚动。
   - 修法：阅读态与编辑态拆分——阅读态用 `ScrollView` + `Text`（随内容撑开，天然可滚动），编辑态以 `TextInput` 自身为滚动主体（恢复默认 `scrollEnabled`）。
   - 附带效果：`editable` + `pointerEvents` 双重开关随 `isEditing` 分支一并消除；编辑态不再支持「拖拽收起键盘」（改由完成按钮/返回键收起）。
   - 已知代价：从阅读态进入编辑态时输入框滚动位置回到顶部。
   - 样式：`scrollContent`/`editorPressable` → `readContent`/`readPressable`；`editor` 保持 `flex:1 + minHeight:200`。

2. **空便签返回判定去掉渲染闭包依赖（中）**
   - `handleBack` 原先用渲染闭包里的 `note.content` 与 `draft` 双条件判定，闭包可能读到过期值。
   - 改为 `flush()` 之后从 `notesStore.getState().notes` 取该 id 的最新行，`content === ''` 即 purge。语义随之变为「返回时已落库内容为空即丢弃」。

3. **移除语义无效的「放弃更改」菜单项（中）**
   - 500ms 防抖早已把内容落库，该操作既不回滚也不清除，属误导性 UI；返回键本就是「保存并退出」。菜单现只保留「归档便签」。
