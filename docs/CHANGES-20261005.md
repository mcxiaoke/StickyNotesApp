# 变更记录 2026-10-05

## 2026-10-05 19:20 移动端端到端防偷窥加密同步落地（对齐桌面端 v1.0）

实现与桌面端逐字节互通的密文同步，并修复两个会静默阻断两端数据相通的路径缺陷：

- **加密纯函数层**：AES-256-CBC + PKCS7、Key = SHA-256(UTF-8(口令))、明文前缀 `SN1:` 魔数守卫、`iv`/`payload` 标准 Base64；Base64 与 UTF-8 编解码自实现（不依赖 `btoa`/`TextDecoder`，规避 RN Hermes 环境差异）。跨平台基准以桌面端 `scripts/crypto_compat/vectors.json` 为准，NIST KAT 与全部应用用例逐字节一致
- **专属密钥两端对齐**：本地密钥文件与桌面端 `VaultSecret.local.cs` 的混淆数组经脚本交叉比对**逐字节一致**（XOR 掩码 `[0x5A,0xA5,0x3C,0xC3]`，解码后为同一 64 字符口令），两端派生同一 AES 密钥，无需任何额外协商；保留公开回落口令以兼容未配置场景
- **双轨子目录路由**（对齐桌面端 `StorageBackendFactory`）：明文 `stickynotes-data/`、密文 `stickynotes-vault/`；WebDAV 根 URL 与 S3 对象前缀自动归一化，幂等追加、切换模式时自动剥离对侧子目录
- **修复：存储根口径不一致（阻断级）**：此前移动端不追加子目录（S3 默认前缀 `stickynotes/`），而桌面端会追加为 `stickynotes-data/`，两端永远读不到同一批数据；现行为与桌面端一致
- **修复：S3 前缀读写错位（阻断级）**：`listAsync` 带 `basePrefix` 而 `get/put/delete` 不带，前缀非空时出现"写进去的对象永远列不出来、每轮全量重传且永远拉不到数据"；现统一走完整对象 key（对照桌面端 `S3Backend.FullKey`）
- **DTO 明密文严格互斥**：密文模式仅输出 `iv` + `payload`、绝不输出 `content`；解析阶段拒绝 `content` 与密文并存、`iv`/`payload` 不成对的文件；解密结果必须通过 `SN1:` 魔数校验，任何失败一律计入跳过，绝不写入乱码
- **口令探针守卫**：密文目录根部 `.auth_verifier`（载荷为固定魔数 `STICKYNOTES_AUTH_OK`），远端不存在时自举创建，存在但校验失败则**整轮同步中止且不写库**
- **同步设置新增「端到端防偷窥加密」开关**（默认关闭，旧配置向后兼容），并明确提示切换开关等于更换数据集、不会自动迁移；保存设置后自动触发一轮同步
- **修复：测试连接卡死**：后端单请求超时由 20 秒收紧为 10 秒，并在 UI 层叠加 10 秒硬超时兜底，网络不可达时必定给出反馈；加密模式下测试连接同时校验口令探针
- **同步状态与指标展示**（对齐桌面端）：主设置页「网络同步」分组与同步设置页统一展示状态与「最近同步：时间（上传 X，下载 Y，远端 N）」，并区分"同步未启用"；指标持久化于 SQLite kv
- **WebDAV Basic 认证**改用自实现 Base64 + UTF-8 编码，移除 `btoa` 依赖
- **URL 输入全角标点自动归一化**：中文输入法下输入的 `：` `／` `。` 会被折算为半角，避免服务器地址解析失败（模拟器实测发现，中文输入法环境下必现）
- **测试**：新增 41 项单测（跨平台向量、密钥对齐、子目录路由、S3 key 口径、全角 URL 归一化、加密上下行、探针拦截、明密文互斥），全量单测 85 项通过、0 失败；另新增 7 项本地 WebDAV 端到端用例（真实 HTTP，含与桌面端 Node 参照实现的双向交叉解密与探针互认），未配置 `WEBDAV_E2E_URL` 时自动跳过
- **模拟器实测（release APK + 本地 WebDAV 真实链路）**：测试连接 4785 ms 成功；加密同步后远端仅有 `iv` + `payload`（无 `content`）；桌面端参照实现可解密移动端上传的密文与探针；反向由桌面端写入密文便签后，应用同步显示「下载 1」并在列表呈现解密正文，双向互通闭环验证通过

## 2026-10-05 16:55 修正图标主体超出官方安全区问题

- 真机（MIUI）与模拟器实测反馈：图标主体几乎顶满遮罩，与其它应用不协调
- 根因：上版按"内容包围盒 = 画布 62%"缩放，但官方安全区是**以画布中心为圆心、直径 66/108dp 的圆**（61%），包围盒角部半径达 62%×√2/2 ≈ 44%，远超安全圆半径 30.5%
- 修正为按径向距离缩放：逐像素计算图形最大半径（实测为内容尺寸的 60.7%），缩放至最大半径 = 画布 30%（前景/单色）/34%（主图标），保证完整落在官方安全圆内
- 重建后模拟器抽屉实测：主体约占遮罩直径 60%，四周留白与 Keep 风格图标一致
